# It's Just Pong

Unreal Engine 5.8 C++ game (single runtime module `IJPong`). Concept: a **roguelite Pong that gets better as you progress**. It starts lo-fi (1972 black and white, heavy CRT, menus included) and upgrades era by era (more colour, more on screen, a cleaner CRT) up to a hard "Pong on steroids" endgame with bosses, multiple ball types, and paddle classes (sprite + ability + per-class skill tree). Two progressions: per-class skill trees, and the game's era, which is the "story". The living design doc is <https://claude.ai/code/artifact/37b5614d-b98a-4d6a-b6ad-9c29eee56660> (read it with the Claude Docs tools). Its proposals and open questions are **not decided** until the user settles them. The earlier "The Lie" concept and its chapter plan (`~/.claude/plans/i-d-like-to-plan-reactive-newell.md`) are superseded.

## How we work
- **Step by step, as a learning exercise.** Claude writes the code in small chunks and walks through it. The user reviews before we move on. One step per turn, never several systems at once.
- **The user owns the design; Claude owns the development.** Design (gameplay rules, content, balance direction, feel, presentation style): present the real choices with a recommendation, then wait. Development (architecture, code structure, data layout, tools, tests): Claude decides and briefly explains the choice in the step summary.
- **All tuning waits for the first playtest.** Every number (difficulty, coins, cooldowns, sizes, speeds, rewards, pacing) is a placeholder, exposed as data. Don't ask about values or spend steps adjusting them until the user has playtested.
- **Build present-first.** Build what the player sees first, add general reusable features as we go, and design levels/chapters later from features that already exist. Don't justify decisions with speculative future chapters.
- The user is comfortable in UE C++: explain architecture and game-specific techniques, not UCLASS/UPROPERTY basics.
- **Every step ends with a build and a commit.** Claude commits at the end of each step without asking. Commit messages end with the Co-Authored-By line.

## Testing
**Integration tests only. No unit tests.** Tests go in `Source/IJPong/Tests/`. They create a real world with arena, ball and paddles, run the simulation, and check gameplay outcomes. Use the `FIJPTestWorld` fixture (`Tests/IJPTestWorld.h`). It runs the real game mode and BeginPlay path and ticks at a fixed 1/60 s.

Run headless (the editor must not hold the DLL; see Build):
```
"C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "<repo>\IJPong.uproject" -ExecCmds="Automation RunTests IJPong.; Quit" -unattended -nullrhi -nopause -nosplash -NoSound -log=IJPTests.log
```
Then grep `Saved/Logs/IJPTests.log` for `Test Completed`. To test without closing the user's editor, copy `IJPong.uproject`, `Source`, `Config` and `Content` to a **short** path such as `C:\IJPT`, then build and test there, and delete it afterwards. The scratchpad path is too long for UBT.

## Build
```
"C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat" IJPongEditor Win64 Development -Project="<repo>\IJPong.uproject" -WaitMutex -NoHotReloadFromIDE
```
The "banned MSVC 14.40–14.43" lines in the output are just UBT listing toolchains it skips (it uses 14.51). They aren't errors.

**If the editor is open, the build compiles but can't link**: the editor locks `Binaries/Win64/UnrealEditor-IJPong.dll`. Reopening the editor afterwards does *not* rebuild it. The editor quietly loads the old DLL, and new classes are missing (`Failed to find object 'Class /Script/IJPong...'`). Live Coding is unsafe for steps that add UCLASSes. The user has OK'd Claude doing this routine:
1. Close the editor gracefully: `(Get-Process UnrealEditor).CloseMainWindow()`, then `Wait-Process -Timeout 90`. It's the same as clicking X, so unsaved work raises the editor's save dialog. If it's still running afterwards, tell the user a dialog is waiting. **Never `Stop-Process` it.**
2. Build in place, then check the DLL's timestamp and size to confirm it really relinked.
3. Relaunch: `Start-Process "C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64\UnrealEditor.exe" -ArgumentList '"<repo>\IJPong.uproject"'`.

**Shader edits (`Shaders/*.ush`)**: the editor caches shader source files. After editing one, restart the editor (routine above) and then recompile `M_CRT` (MCP `MaterialTools.recompile`, which raises on HLSL errors). Recompiling without a restart silently uses the old file.

## Editor access (Unreal MCP)
The engine's experimental `ModelContextProtocol` plugin is enabled, along with the Editor, AutomationTest, LiveCoding and UMG toolsets. The server runs inside the editor at `http://127.0.0.1:8000/mcp` (`unreal-mcp` in `.mcp.json`, auto-start on). Its tools exist only while the editor is open, and they disconnect during a close/rebuild/relaunch. Ask before doing anything destructive in the user's open editor.
- `call_tool` takes the **short** tool name (e.g. `create`), not the fully-qualified name `describe_toolset` lists.
- `DataAssetTools.create` can make `UDataAsset` subclasses such as InputAction and InputMappingContext. `ObjectTools.set_properties` edits them. Instanced sub-objects (e.g. IMC modifiers) are passed as class paths.

## Decisions so far
- Vs AI only, no networking.
- **Controls** (the user's layout, `IMC_Pong`; keyboard-only, no mouse): keyboard Up/Down arrows move, W/S aim (the Catcher), Space = class skill (also confirms on menus), Z = run ability, X = spell and C = item/consumable (both reserved until those exist), A/D or Left/Right step through menus and the map. Gamepad (my pick, mirroring the letters): left stick / D-pad up-down move, right stick aims, A = class skill, B = run ability, X = spell and Y = item (reserved), left stick / D-pad left-right step menus. Test-mode debug keys live in `IMC_Debug` and must not take any of these.
- C++ owns rules and simulation. Data Assets and BP own tuning and content.
- The ball is a custom kinematic, sweep-based mover (not Chaos).
- Git + LFS: `.uasset`/`.umap`/`.png`/`.wav`/`.fbx` are tracked by LFS.
- The `PongBall` trace channel defaults to **Ignore**: objects must opt in to block the ball.
- Scoring = **goal boxes** that block the ball's sweep (not a goal-line position check).
- Paddle bounce: **60°** max edge angle, **no spin** (pure 1972).
- Game modes subclass **`AIJPGameModeBase`** (finds the arena, player gets the left paddle, AI the right). **`AIJPTestGameMode`** is the project default for now: match after match on any level (rules from `MatchRules` in config, `/Game/Match/DA_Match_FirstTo5`), with debug keys R (new match), F (serve now; starts a new match once one is over), T (hand the player's paddle to an AI), -/= (opponent skill), [/] (cycle eras), B (launch an extra ball of a random `ExtraBallTypes` type) and `.` (debug overlay; not F1, which the engine binds to wireframe view in development builds; `AIJPTestHUD`, on by default; its lines come from `AIJPTestGameMode::GetDebugLines`, so add new tool state there). Real modes (the run map) come later as separate subclasses.
- Matches are run by **`UIJPMatchComponent`** on `AIJPGameModeBase` (`GetMatch()`): serve, damage, win check, `OnMatchEnded(Winner)`; many matches can run in one level. **Matches are won on health, not points** (the user's call, in every era): each side has float health; `ApplyDamage(Side, Amount)` is the one way it drops (goals now: the ball's `Points` x the rules' `GoalDamage`; spells later) and `OnHealthChanged(Side, Health, Damage)` fires before any match end; 0 = the other side wins. `GetGoals` counts goals (banter, tests). The seven-segment number over each half shows that side's health rounded up and flashes on damage. Rules are **`UIJPMatchRules`** Data Assets (`StartingHealth`, 0 = endless: no health, the numbers count goals; `GoalDamage`; serve delay/angle; assets `DA_Match_FirstTo3/5/7` hold 3/5/7 health, names kept from before). Match end is 1972 style: the ball stops and the winner's number blinks (`AIJPArena::ShowWinner`) until the next `StartMatch`.
- **Multi-ball**: the arena owns `Balls` (`GetBall()` = the main ball, always exists; `AddBall` reuses idle balls or spawns) and relays `OnBallGoal(Ball, Side)`. Each goal scores that ball's `Points` and takes it out; the next serve comes once the court is empty. Balls pass through each other. `UIJPMatchRules::ServedBalls` lists the types served each point (alternating direction; empty = one default ball); `LaunchExtraBall` adds one mid-rally. The AI defends the ball that reaches its lane first.
- **Ball types** are `UIJPBallType` Data Assets (size, speeds, points, colour) in `/Game/Balls` (Standard, Heavy, Swift; the values are first passes). A type's colour shows only when the era palette sets `bBallTypeColours` (Cabinet off, Arcade on). **Behaviour balls** (the user's first batch, served by both sides: rivals/bosses via their rules' `ServedBalls`, the player via `_Ball` reward cards and shops) are data on `UIJPBallType`, freely combined: **Ghost** `GhostBand` (hidden while within that fraction of the half-width from the net; `AIJPBall::IsGhosted`), **Twin** `bSplitsOnFirstHit` + `SplitSpread` (the arena fans it into two on its first return with `UIJPAbility_Split::FanOut`; both halves are marked split), **Bomb** `StunOnGoal` (a goal stuns the paddle it beat: `AIJPPaddle::Stun` ignores input), **Leech** `HealOnGoal` (a goal also heals the scorer: `UIJPMatchComponent::Heal`). Assets `DA_Ball_Ghost/Twin/Bomb/Leech` (values are first passes), all in the test mode's B list. "Twin" is my placeholder name (the Splitter class owns "Splitter").
- **Abilities** are custom (no GAS): `UIJPAbilityComponent` on each paddle has two slots (`ClassSkill`, `RunAbility`), each with a cooldown counted from activation. An ability is a C++ subclass of `UIJPAbility` (behaviour) plus Data Assets made from it (tuning, `/Game/Abilities`); equipping gives the slot its own copy (`DuplicateObject`) for runtime state. The class skill comes from the paddle's class (`UIJPPaddleClass::ClassSkill`); the run ability is `PlayerRunAbility` in the test mode's config (Grow) until runs exist. Keys: see **Controls** below. The arena tells a paddle's abilities when it returns a ball (`HandleBallHit`). Armed skills (`UIJPAbility::IsArmed`: Smash, Curve shot, Split) show one generic cue: a halo behind the paddle pulsing at 3 Hz in its palette colour (a halo, not brightening, because white can't get brighter after tonemapping), plus a rising two-note `Arm` chirp from the tone set. **Rival abilities** (the user's design: rival-only skills, soft counters that make a class's matchup harder but never unwinnable, plus wildcards; roster Breaker, Magnet, Glutton, Snare, Reader, Scorcher, Mirror, Jammer, Warp, placeholder names): `UIJPRival::RivalSkill` replaces the class skill in the rival paddle's slot (`SetRival`); the class stays its body. Any ability can have a `Telegraph` wind-up: the component shows the armed halo and plays the tone set's `Warn` buzz, then fires (`IsWindingUp`; cooldown counts from the press). The AI controller presses a slot whenever it's ready and the ability's `WantsAIUse()` says so; only rival abilities answer it, so AI paddles never use class skills. Built: **Snare** (the other paddle's top speed x `SpeedMultiplier` for `Duration`, through `AIJPPaddle::SetSpeedScale`, which also shortens dashes; used as a ball heads for the other side). **Breaker** (armed; its next return makes that ball pierce barriers, `AIJPBall::SetPiercing`, until its next paddle hit, serve or goal; the barrier stays up for the rest; the AI arms it for an incoming ball only when the other side has a barrier up or owns Barrier). **Magnet** (for `Duration`, each ball heading its way is softened once with `AIJPBall::Dampen`: the curve turns `CurveScale` as fast and a smash keeps `BoostScale` of its extra speed; the AI uses it on an incoming curving or boosted ball). **Glutton** (for `Duration`, while two or more balls are in play it swallows the one on its half heading in closest to its goal: `ResetBall`, no goal; one per use; the AI opens up when several balls are in play and one is heading its way). **Mirror** (wildcard: listens to the other paddle's `OnActivated` and remembers the last ability's asset, `UIJPAbility::GetDefinition`, class skill or run ability; when used it makes its own copy, `Init`s it on this paddle and runs it inside itself, passing ticks and ball hits on; nothing to copy = can't activate; the AI uses it as a ball heads its way). **Jammer** (wildcard: locks the other paddle's class skill for `Duration`, `UIJPAbilityComponent::LockSlot`, and fills the screen with static, `UIJPCRTComponent::Jam`, which raises the CRT material's `NoiseStrength` over the era's own; eras without a CRT get no static yet, their look is undecided; the AI jams when a ball heads at the player and their class skill is ready). **Warp** (wildcard: the ball heading at the other side that's furthest from them jumps to the mirrored height, at least `MinJump`, inside the walls, via `AIJPBall::Warp`, which keeps speed, angle, curve and boost; the AI fires as a ball crosses the net toward them). **Reader** (hard for the Catcher: during `Duration`, while the other paddle holds a ball, it predicts where the shot would land at the current aim, a catch's `GetFireAngle`, and drives its AI there with `AIJPPaddleAIController::SetReadTarget`, cleared on release; the AI uses it once the other side arms a catch or holds a ball). **Scorcher** (hard for the Catcher: during `Duration` its returns are hot, `AIJPBall::SetHeat`; the next paddle to touch a hot ball reads `GetArrivalHeat` and the ball cools; a catch holds for `Heat` less of its hold time; the AI uses it against a Catcher with a ball on its way). All nine rivals are built. Assets `DA_Ability_<Name>`, `DA_Rival_<Name>` (Classic bodies for now, in the test mode's V list).
- **Run map** (roguelite layer): `UIJPActConfig` (`/Game/Run`, first act `DA_Act_Cabinet_1`) = map shape (rows **top to bottom**, lanes, paths), node weights, and an `FIJPEncounter` per fight type (rivals, rules, opponent skill, coins) + rest heal. `FIJPRunMap::Generate` (seeded) walks non-crossing paths down: Match on top, Rest above a lone Boss at the bottom. `UIJPRunSubsystem` (GameInstance) holds the run: map, position, visited, health, coins; Rest heals on entry; a win pays; the boss wins the run; 0 health loses it. Run health is a float and the player's match health: `AIJPRunGameMode` sets the player's side from it (`UIJPMatchComponent::SetHealth`) after `BeginMatch` (the rival starts at the rules' `StartingHealth`) and takes every `OnHealthChanged` damage off the run, so losing a match is running out of run health, which ends the run. Event isn't built yet. **Shop** (the user's design: items plus the same kinds of cards as the reward picks, each for coins; buy as much as the coins cover): shop nodes come from the act's `ShopWeight`; entering one rolls `ShopChoices` from `ShopRewards` (`UIJPRunSubsystem::GetShopStock`); `BuyFromShop` charges the reward's `Price` and grants it; `LeaveShop` opens the map. `AIJPRunGameMode`'s Shop phase shows the stock as cards with prices plus LEAVE (A/D, Space buys or leaves; the pick stays put after a buy). **Rewards**: winning a Match or Elite offers a pick of `RewardChoices` (3) from the act's `MatchRewards` / `EliteRewards`, plus a Skip card for `SkipCoins`; the boss gives no pick (the act ends). Rewards are `UIJPReward` Data Assets (`/Game/Rewards`): `_Modifier` (paddle length, paddle speed, max health, class-skill cooldown; stacks), `_Ball` (every serve adds that ball type, via `UIJPMatchComponent::SetExtraServedBalls`) and `_Ability` (fills the run-ability slot, replacing; not re-offered while held). What's gathered is the run's `FIJPRunLoadout`, applied to the player's paddle/serves at every fight (`AIJPRunGameMode::ApplyLoadout`; `AIJPPaddle::SetRunScales` is separate from Grow's `SetLengthScale`). The pick is shown as cards by the map view (`ShowCards`). Run abilities so far: Grow, Freeze (all balls stop 0.5 s), Slow-mo (balls at half speed 2 s, paddles unaffected). `AIJPRunGameMode` (level `Run_01`) plays it: `AIJPRunMapView` draws the map on its own 4:3 CRT camera (bright = can go, mid = visited, dim = rest); A/D (`IA_UIStep`, via the game mode's `HandleUIStep`/`HandleUIConfirm` hooks) picks, Space confirms; every goal against the player costs 1 health; results show for `PostMatchDelay` then back to the map. Tests can pick a game mode via `FIJPTestWorld`'s third argument.
- **Meta currencies** (kept between runs, shared by all classes; spent on the skill trees, which aren't built yet): **skill points** from depth reached, paid by every run at its end, win or lose (`SkillPointsPerRow`), and **boss tokens** for beating a boss (`BossTokens`, both on the act). The names are placeholders. `UIJPMetaSubsystem` (GameInstance) keeps them in a `UIJPMetaSave` and saves on every change (slot `IJPongMeta`; automation tests use `IJPongMeta_Tests`, so they never touch real progress). The run's end screen shows what was earned and the totals. **Skill trees**: `UIJPSkillTree` per class (`UIJPPaddleClass::SkillTree`; only `DA_Tree_Classic` so far, placeholder nodes): 3 branches off a root (the class skill); a node needs its parent owned; stat nodes cost skill points, keystones boss tokens. Node effects are data: paddle length/speed, skill cooldown, return angle (`AIJPPaddle::SetReturnAngleBonus`), or a named `SkillUpgrade` that the ability reads via `UIJPAbility::GetUpgrade` (Smash: Power, Curve, ExtraHits, Split). `UIJPMetaSubsystem` keeps owned nodes in the save (`"<tree asset>/<node id>"`, so don't rename node Ids) and sums them with `GetBonuses`; the run mode applies them with the loadout at every fight. The tree screen (map view `ShowTree`) opens from the run's end screen: A/D pick, Space buys or START RUN.
- The AI is an **`AAIController`** so behaviour trees can drive abilities later.
- **Spells** (the user's design: a fourth slot, `EIJPAbilitySlot::Spell`, on X / gamepad X; charged by returns; telegraphed and dodgeable; never a goal; rivals can cast them, only the boss for now): any ability with a `ChargeCost` is charge-gated instead of cooldown-gated; every return adds 1 (`UIJPAbilityComponent::AddCharge`) and casting empties it. The Spell slot's charge shows as pips under that side's health (`UIJPChargePipsComponent`, blinking when full). `UIJPAbility_Spell` (assets `/Game/Spells`: Lightning = short warning, small hit; Fireball = slow travelling shot, big hit) spawns an `AIJPSpellStrike` aimed at the other paddle's lane where it stood at the cast: two blinking lines mark the zone, then after `Delay` it lands (damage via `ApplyDamage` if the paddle overlaps the zone). Strikes register with the arena; the AI steers clear of zones about to land on it (`AIJPPaddleAIController::AvoidStrikes`) and casts as a ball heads for the other side. `UIJPRival::Spell` equips a rival's. Test mode gives the player `PlayerSpell` (Fireball). **Unlock**: the Spell slot is bought once for every class with boss tokens (`UIJPMetaSubsystem::UnlockSpellSlot`, `SpellSlotCost` config, saved as `bSpellSlotUnlocked`) from the SPELLS box beside START RUN on the between-runs tree screen (`AIJPRunMapView::TreeUnlockSpells`). Until then runs never equip or offer spells; after it, `UIJPReward_Spell` cards (elite picks and shops) set the run's `FIJPRunLoadout::Spell`, equipped at every fight. The Cabinet act's boss is `DA_Rival_Boss_Cabinet` (a Bulwark that casts Fireball); other rivals have no spell yet.
- **Items** (the user's design: one-use consumables on C / gamepad Y, no cooldown; carry ONE, a new one replaces it; from shops, match reward picks and boss drops; usable only in matches): an item is a `UIJPAbility` subclass (`Abilities/IJPItem_*`, assets in `/Game/Items`) equipped in the third slot, `EIJPAbilitySlot::Item`; using it spends the slot (`UIJPAbilityComponent::HasItem`) while any effect finishes. **Patch** heals through `UIJPMatchComponent::Heal` (`OnHealthChanged` with negative damage, which the run turns into `UIJPRunSubsystem::RestoreHealth`). **Shield** raises your barrier until one ball bounces off it (`AIJPArena::OnBarrierHit`, sent by the ball); a Breaker shot pierces it. The run carries `FIJPRunLoadout::Item` (equipped at every fight, cleared when used); `UIJPReward_Item` cards give one; an act's `BossItems` drop one at random for beating the boss. Test mode puts `PlayerItem` (Shield) in the slot at every new match (R refills). Mirror never copies items. Shops sell them too.
- **Paddle classes**: `UIJPPaddleClass` (`/Game/Classes`: Classic, Striker, Bulwark, Curver, Splitter, Catcher) = name + `UIJPPaddleProfile` (base stats: size, max speed, ramp, flicker; `/Game/Paddles`) + class skill; later a sprite and skill tree. Profiles stay pure stats. Each arena has a class per side (`LeftPaddleClass` / `RightPaddleClass`, default Classic via config); `AIJPPaddle::SetPaddleClass` switches live. Classes are plain boxes for now (sprite slot comes with the first art). Class skills: Classic = Smash, Striker = Dash (`AIJPPaddle::Dash`), Bulwark = Barrier (`AIJPArena::SetBarrierUp`, a ball-blocking line inside each goal line), Curver = Curve shot (`AIJPBall::Curve`, bends toward the paddle's motion, mirrored by walls), Splitter = Split (fans the return into two balls of the same type). **Catcher** (the user's sixth class) = Catch: arm it and the next return is caught (`AIJPBall::Hold`: in play, not moving, riding the paddle's face); the paddle keeps moving while the player aims (`AIJPPaddle` aim angle: right stick `IA_Aim` = absolute direction, W/S `IA_AimKeys` turn it at `KeyAimSpeed` deg/s from the input settings; no mouse; the aim starts at the return's own angle; a thin aim line shows); letting go of the class-skill button (Completed event -> `UIJPAbilityComponent::Release` -> `UIJPAbility::OnButtonReleased`) fires it at the return's speed (`AIJPBall::Release`, which raises the ball's angle limit so walls keep a steep shot), or it fires itself after `HoldTime`; `AimLimitDeg` 70 is steeper than a bounce, for bank shots. `DA_Class_Catcher` uses the default profile for now. Class stats and skill numbers are first passes.
- **Bosses** (the user's design: unique bosses with real names, their own abilities/spells, sprites and backdrops, and phases at health thresholds): a boss is a `UIJPRival` with `BossLength` (length at full health, shrinking to 1x as it loses health) and `Phases` (`FIJPBossPhase`: `AtHealth` fraction, `Pause` freezing every ball, a `Line`, a new `Skill`, a new `Spell` charged and ready, `SplitGap`). `UIJPBossComponent` (on the game mode) follows the boss side's `OnHealthChanged`, and `BeginMatch` restarts it in its first form. Paddles can split in two (`AIJPPaddle::SetSplitGap`: two blocking halves, the ball bounces off the half it meets, the AI lines a half up). Spells can drop several strikes at once (`Strikes`, `StrikeSpacing`). **Bulkhead** (`DA_Rival_Bulkhead`, the Cabinet act's boss, a Bulwark body, 3x long): phase 1 plain; at 2/3 its own spell **Brickfall** (`DA_Spell_Brickfall`: three strikes across your lane with gaps to slip through); at 1/3 it crumbles in two (gap 50). Its lines are placeholders. In the 1972 era bosses are unique by shape and behaviour; sprites and backdrops come from the Arcade era on. It's in the test mode's V list.
- **Rivals**: `UIJPRival` (`/Game/Rivals`) = name + class + AI profile (style) + PreMatch/Win/Loss conversation lists (one picked at random). Difficulty is not the rival's: it stays the arena's `OpponentSkill`. `AIJPGameModeBase::SetRival` applies one live. The four rivals are placeholders ("<Class> Rival") for the user to name and write; only Striker has a (placeholder) intro. Test mode: N cycles your class, V cycles the rival (including none) and restarts the match; `StartingRival` (config index, -1 = none) picks one at launch.
- **Chat bubbles / narrative**: every paddle has a `UIJPSpeechBubbleComponent` (world-space, under the CRT, behind paddles and balls so it never hides play; typewriter with a blip per other letter from the tone set's `Talk`; auto hold from length). `UIJPConversation` assets (`/Game/Narrative`) = lines of {Player/Opponent, text, hold}. `AIJPGameModeBase`: `BeginMatch` plays the rival's PreMatch and holds the first serve until it ends (`UIJPMatchComponent` serve hold); the rival's Win/Loss conversation plays over the winner blink; `PlayConversation` is banter over live play (never pauses). Text uses `M_PongText` (unlit; colour = the speaker's palette colour). Bubbles don't wrap: put line breaks in the text. **Bubble shape**: one panel drawn by `M_PongBubble` (arena config `BubbleMaterial`; a shader box + border + tail toward the paddle, parameters Shape/Tail/Style/Fill/Ink). The era sets `BubbleCornerRadius` (0 = square) and `bSmoothBubbleTail` (false = a pixel-stepped tail): Cabinet square + stepped, Arcade rounded (8) + smooth. It's read when a line starts. **Mid-rally banter**: each rival has `Banter` entries (event, conversations, chance) plus `BanterCooldown`, `LongRallyReturns` and `VoicePitch`. Events: RivalScored/PlayerScored, the *First variants for the match's first goal, Rival/PlayerMatchPoint, LongRally. `UIJPBanterComponent` (on the game mode) listens to `UIJPMatchComponent::OnPointScored` and `AIJPArena::OnBallReturned`, takes only the highest-priority event with lines (match point > first goal > goal), rolls its chance, respects the cooldown, and replaces any banter on screen. It never plays while the serve is held (pre-match) or after the match ends. **Babble**: each typed letter plays a `Talk` tone pitched by the letter (±`TalkRange` semitones, vowels higher) times the speaker's voice (`SetVoicePitch`; the opponent defaults to 0.8, a rival uses its `VoicePitch`).
- **No difficulty settings in the game.** Difficulty is a designer-authored spectrum: each arena's `OpponentSkill` (0 hopeless .. 1 near-perfect) is read through `FIJPSkillRange` pairs (value at skill 0 / at skill 1) in the `UIJPAIProfile`. Skill 0.5 = the original tuning. In the test mode, `-` / `=` nudge it live.
- Sound: the ball broadcasts events (`OnPaddleHit`, `OnBounce`, `OnGoal`). The **arena** maps them to beeps from a `UIJPToneSet` Data Asset, played by a C++ square-wave synth (`UIJPToneSynthComponent`). The synth suits this 1972 level, but **the user wants custom sound assets eventually**. Add those at the arena's event → sound mapping (e.g. an optional `USoundBase` per event), not in the ball.
- Screen look: **CRT post-process** (scanlines, gentle curvature + vignette, phosphor glow, plus "rough tube" params that default to 0: soft beam, raised black level, rolling hum bar, static noise; era 1 turns them up, sync jitter was rejected for readability) via `UIJPCRTComponent`, which works on **any camera**, not just the arena's (the user wants it on menu cameras too). Material `M_CRT` (a Custom node that `#include`s `Shaders/IJPCRT.ush`), tuned per era in material instances (`MI_CRT_1972`, draft `MI_CRT_Arcade`).
- **Eras**: a `UIJPEra` Data Asset per era (`/Game/Eras/DA_Era_*`) bundles CRT material (empty = no CRT), tone set and a `FIJPPalette` (background, walls, net, score, each paddle, ball). `UIJPEraSubsystem` (GameInstance) holds the current era, the ordered list (`Eras` in config; the first is where the game starts) and `OnEraChanged`. Arenas and every `UIJPCRTComponent` follow it live. Per-arena `ToneSet` / per-component `CRTMaterial` are overrides that ignore the era. Pieces are coloured through per-role instances of `M_PongUnlit` (`Color` param) made by the arena (`GetPaletteMaterial`). `DA_Era_Arcade` is a placeholder draft.
- Playfield is **4:3, pillarboxed**. Scores are **chunky seven-segment** digits. Walls are visible by default (`bShowWalls` toggle; the user hasn't decided this yet).
